# 音乐窗右键及其它鼠标操作分析

> 本文保留修复前的分析快照；下文“当前”指分析时的旧 DLL。随后用户授权实施，并明确不实现“每周推荐”列表。已完成的修正和验证见 [MOUSE_BEHAVIOR_FIX.zh-CN.md](MOUSE_BEHAVIOR_FIX.zh-CN.md)。

分析日期：2026-10-27。对象为指定的 TTPlayer5790x / TTPlayer5790z、当前 `ttpbrowser` 源码，以及 `rebuild/build/Release/ttpbrowser.dll`。本轮只增加分析文档和隔离探针，没有修改产品实现或替换发行文件。

**结论：音乐窗应按外框、网页、下载管理分别处理鼠标。当前实现已有基本操作，但仍存在明确的交互差异，不能称为完全复原。** 尤其是外框任意右键进入推荐菜单、下载中双击播放、底部链接在内嵌浏览器打开，以及“删除文件”的实际删除方式。

原版证据来自已保存的 REA/Ghidra 结果；从另一份全量反编译提取的新增函数均核验了目标机器码。原版没有在本轮运行。下文“原版确认”指静态代码及资源确认；“探针复现”只针对当前 Release DLL，不代表已运行原版或恢复历史网页。

**右键必须先判断所在区域。** 原版结构为 `TTPlayer_BrowserWnd` 外框，其内有独立皮肤按钮、滚动链接、`AtlAxWin71 / MSHTML` 网页，以及含标准 ListView 的下载子窗。当前 DLL 将外框控件画在一个 HWND 中，下载歌曲列表则改为自绘 HWND，网页仍由独立引擎子窗口处理。

| 右键位置 | 原版证据 | 当前重建行为 | 判断 |
|---|---|---|---|
| 外框空白、顶部按钮、底部链接 | 已追踪的外框和按钮分派没有专用推荐菜单分支 | 外框 `WM_CONTEXTMENU` 不检查来源或位置，统一调用 `Recommendations()` | 推荐菜单是重建选择，缺乏原版依据 |
| 下载页分类空白、顶部横幅、帮助按钮 | 分类区没有歌曲列表的 `NM_RCLICK` 命令菜单分支 | 默认消息向父窗传递，最后进入外框推荐逻辑 | 隐藏消息探针已确认上述区域都会到达外框 `WM_CONTEXTMENU` |
| 网页内容 | 原版宿主允许 MSHTML 默认上下文菜单；网页仍可能自己处理事件 | IE 使用默认菜单；WebView2 明确启用默认菜单 | 原则一致，菜单项目和文案不保证相同 |
| 下载列表有效行 | `NM_RCLICK → 004242CD`，依据分类显示任务或已下载菜单 | 列表自行处理 `WM_CONTEXTMENU`，不走外框推荐菜单 | 基础菜单已恢复，选中、焦点、启禁及部分命令结果仍有差异 |
| 下载列表表头、滚动条、空白无效行 | 原版任务菜单要求有效通知行 | 当前直接返回，不弹任务菜单，也不传给外框 | 探针确认表头、空白不进入外框菜单 |
| 键盘菜单键 / Shift+F10 | 原版依赖标准控件及通知，位置尚未独立验证 | 列表收到 `(-1,-1)` 时在列表左上 `(10,表头高+10)` 弹出；外框推荐菜单始终用当前鼠标位置 | 应与物理右键位置分别设计和验证 |

当前外框路径在 [browser_window.cpp](../src/browser_window.cpp) 的 `Proc / Recommendations`：有推荐歌曲时列出最多 500 首，选择后提交播放；没有推荐歌曲但存在 `link_url_` 和 backend 时，右键会直接调用 `Navigate(link_url_)`。后者连菜单都不会弹出，也没有先切回音乐页。因此一次下载页空白右键可能改动隐藏浏览器的页面。这个导航副作用由源码确认，本轮没有通过真实网页运行它。

原版 `AddRecomdSound / ClearRecomdList` 经主窗消息 `0x784` 操作 1/2 进入播放器的命名播放列表模型，不是外框右键菜单。这比“没有找到菜单”更明确：当前独立推荐菜单不能作为原版推荐接入已经复原的证据。原版最终列表的本地化名称不在本文中推定。

**网页区不应因为外框菜单有问题而统一禁用右键。** 原版 `IDocHostUIHandlerDispatch::ShowContextMenu` 槽指向 `0040BE81`，返回 `E_NOTIMPL` 且不改写输出；ATL 的 `0040681D` 保留默认 `S_FALSE`，交给 MSHTML 显示菜单。`ShowUI` 隐藏浏览器菜单栏/工具栏是另一回事，不能用它推断右键被禁用。

原版宿主也没有在 `GetHostInfo`、`GetDropTarget`、`FilterDataObject` 中定义专用网页双击或拖放规则。网页内链接点击、选字、双击、滚轮、中键和侧键的实际表现仍由浏览器和网页共同决定。安装包中的加载占位页不含当年完整门户脚本，故无法仅凭安装包恢复“网页歌曲右键菜单”及其全部项目。

当前 [ie_backend.cpp](../src/ie_backend.cpp) 和 [webview_backend.cpp](../src/webview_backend.cpp) 有两项可见差别需要单独约定：

| 网页操作 | 当前 IE | 当前 WebView2 | 原版确认范围 |
|---|---|---|---|
| 请求新窗口的链接/手势 | 取消 NewWindow2/3；有 NewWindow3 URL 时改在当前窗口导航 | 标记已处理，仅用户发起且为 HTTP(S) 时当前窗口导航 | 已核验原版事件表没有对应处理；不能称当前策略与原版相同 |
| 触发浏览器原生下载 | 取消并显示“请使用页面的音乐下载按钮”错误 | 取消引擎下载；可信页面的 URL 转交播放器下载队列 | 原版该事件表没有 FileDownload 处理；历史实际结果未知 |

浏览器“另存为”等原生命令与网页调用 `AddDownloadInfo` 不是同一入口。WebView2 禁用开发者工具、启用默认菜单，也不等于逐项复刻 IE 菜单。

**下载列表右键的基本结构已恢复。** 原菜单资源为 MENU 130（下载中）和 MENU 394（已下载）。

| 分类 | 菜单项（命令 ID） | 原版启禁与当前差异 |
|---|---|---|
| 下载中 | 开始下载 32960；暂停下载 32961；删除任务 32962；全部选中 32963 | 原版单选等待/下载中禁开始，失败/暂停禁暂停；多选移除全选，开始/暂停都保留可用。当前多选也按所选状态额外禁用开始/暂停 |
| 已下载 | 播放歌曲 32972；添加到列表 32973；删除记录 32966；删除文件 32967；重新下载 32968；全部选中 32974；浏览文件 32975；发送到→文件夹 32980 | 原版与当前都在多选时禁浏览文件；原版保留动态发送扩展位置，当前仅有文件夹 |

原版有效行右键会 `SetFocus` 到列表，其选中变化依赖 `SysListView32` 默认行为。当前自绘列表自行规定：右键未选行，清掉旧选择并单选该行；右键已选行，保留多选。当前没有对应 `SetFocus`。原版所有 Ctrl/Shift 加右键的组合仍需运行验证，不能仅凭标准控件名称认定逐项一致。

菜单名称相同不代表命令效果相同，特别是以下操作：

| 操作 | 原版实现 | 当前实现 |
|---|---|---|
| 删除任务 / 删除记录 | 与删除实体文件分开的命令 | 移除队列/记录，保留已下载文件 |
| 删除文件 | `00424C0C` 调用 Shell `FO_DELETE + FOF_ALLOWUNDO`，请求可撤销删除；可选择同时处理已关联歌词 | 只有歌曲删除确认，调用 `DeleteFileW`；不经回收站、不处理关联歌词 |
| Shift+Delete（已下载） | 走删除文件路径，仍请求 Shell 可撤销删除 | 忽略 Shift，仍走删除记录 |
| 添加到列表 | 提交目标列表选择/添加流程 | 提交宿主回调，由 EXE 选择列表 |
| 发送到文件夹 | 原版 Shell 数据传送路径 | 文件夹选择后逐个 `CopyFileW`，目标同名存在时报错；动态设备扩展未恢复 |

原版“允许撤销”是 API 请求，不承诺任何磁盘或路径都能进入回收站。本轮没有运行任何删除命令。

**单击、双击与选择存在几处最直接影响使用的差异。** 原版下载列表不是“全部双击播放”。

| 手势 | 原版 | 当前重建 |
|---|---|---|
| 已下载歌曲第 0 列播放图标单击 | `NM_CLICK → 004252CB`，有效行且第 0 列时播放 | 只选择该行，没有播放 |
| 下载中任务双击 | `004244B1`：状态 2 暂停；其它通过开始函数处理，状态 1/3/5 可开始 | 不看分类，统一播放该任务远程 URL |
| 已下载歌曲双击 | 播放 | 播放本地文件 |
| 空白处单击后双击 | 原版双击函数也读现有 selection；是否先被标准控件清选尚未运行确认 | 无效行单击不清旧选择，双击又不校验行，最终播放旧选中项；已探针复现 |
| 普通单击 / Ctrl / Shift | 标准 ListView 的选择状态参与后续命令 | 普通单选、Ctrl 切换单项、Shift 选连续区间、Ctrl+Shift 追加区间 |
| 重复点击当前分类 | `00420E99` 的相同分类保护通常保持现有状态 | 每次清空选择、焦点、锚点并滚回顶部 |
| 悬停播放图标或状态 | 已下载图标有手形与“播放歌曲”提示；下载中有状态提示；名称列有元数据提示 | 没有对应图标手形和列表 tooltip |

原版空白双击的最终表现保留为未知；不能把当前探针发现进一步写成“原版绝不会发生”。但当前空白双击触发旧歌曲播放本身已经确认，应独立修正命中校验。

**表头、滚动及分隔条还有更细的行为差别。**

| 区域/操作 | 原版证据 | 当前行为 |
|---|---|---|
| 下载中表头左击 | 表头开关关闭，`0041DDBD` 吞左按，不触发普通标题排序 | 左按立即排序 |
| 已下载表头左击 | 允许标题点击，重复同列反向；少于两行不排序 | 左按立即排序，没有按下后移出取消的阶段 |
| 列边界拖动、双击自动列宽 | 原版表头拦截边界左按和双击，不是常规可调宽表头 | 没有列宽调整；随整个列表宽度按权重分配 |
| 当前排序规则 | 原版完整比较器未全部追完 | 大小按数值、状态按枚举；其余按显示文字，所以进度和速度是字典序，日期只显示月日 |
| 滚轮 | 标准 ListView 加 ttpcomm 皮肤层，精确滚量未运行核实 | 每 120 delta 固定滚 3 行；不读取系统滚动行数；小于整数像素的余量不累计；无专用横向滚轮路径 |
| 滚动条 | 原版完整重复计时路径尚未追完 | 上下箭头单击一行、轨道一页、滑块捕获拖动；无按住自动重复逻辑 |
| 左分类分隔条拖动 | 原版有捕获和分隔位置调整 | 5 像素命中带，宽度限制 40 到客户区宽−100 |
| 分隔条中央按钮 | `0041C1EB / 0041C8F5 / 0041C941`：单击收起到 0，保存原宽；再次恢复 | 只按拖动处理，没有收起/恢复 |
| 列表行拖动 | 有拖影、插入位置、捕获，以及右按/Esc 取消框架；owner-data 下载列表最后是否同步重排仍未追通 | 没有这套行拖动框架，也未实现 OLE 文件拖出 |

不能据通用行拖动代码的存在宣称原版下载顺序已确认可任意重排，也不能据它宣称支持拖文件到资源管理器。网页自身的拖放又属于浏览器层，应与原生下载列表分开验证。

**顶部控件和底部链接也需要分别处理。** 原版顶部按钮是独立 HWND，当前为同一窗口内的命中矩形。两者都支持按下、移出、移回、释放时的状态更新；当前只有在释放仍命中原控件且控件启用时才执行命令。下载页的后退、前进、刷新禁用。

| 控件 | 当前左键动作及原版关系 |
|---|---|
| 关闭 | 隐藏音乐窗，后台任务继续；不是关闭播放器 |
| 音乐窗 / 下载管理 | 切换两个子视图；原版同样是视图显隐切换 |
| 后退 / 前进 / 刷新 | 操作浏览器历史、刷新或重试错误页 |
| 启动时显示 | 翻转自启动显示设置并通知宿主 |
| 底部链接 | 当前优先在音乐窗内导航；无链接时可弹推荐菜单或回首页，区别于原版滚动链接 |

原版顶部按钮默认采用手形光标；当前外框除了尺寸调整区域均返回箭头。原版按钮在 hover 阶段就使用捕获，当前只在按下后捕获，两种内部机制不完全一样。原版按钮类样式不含 `CS_DBLCLKS`，当前外框也没有；普通快速双击通常成为两次点击，启动复选框可能翻转两次，并非特殊双击命令。原版和当前外框均未找到标题双击最大化的专用实现。

原版底部 `linktxt` 是单独的轮播/滚动链接控件：`0040C20D` 用实际文字宽度决定命中范围；`0040C68D` 命中后显示手形并暂停轮播；离开且有多条目时恢复计时；`0040C636` 创建下划线字体。`WM_LBUTTONUP → 0040C701 → 004C2D7F → ShellExecuteW` 打开外部浏览器路径，辅助函数含 IE/关联处理，不能简单保证总是现代系统默认浏览器。当前只保存一组文字/URL，以整个皮肤预留矩形命中、静态省略绘制，使用箭头并在内嵌窗口导航，没有恢复这些滚动链接行为。

**拖动外框与拖动内部控件是两套操作。** 当前 `BackgroundHit` 先排除按钮，再判定边缘和内容区：左/右 5 像素、上 4 像素、下 5 像素，沿边的角命中扩展至 16 像素。内容区交给子窗，其余皮肤空白作为移动区域。透明区域依窗口 region 排除。默认皮肤最小尺寸为 480×486；其它皮肤按背景尺寸且不小于 320×240。

原版 `00410832` 使用系统尺寸边框指标并在大于 3 时取 4，角区沿相邻轴取两倍边宽。因此当前更大的角命中区域是重建设计，不是原版像素级命中复刻。外框缩放的九宫格绘制与命中检测是不同问题，见 [九宫格分析与修复](NINE_PATCH_FIX.zh-CN.md)。

当前外框按下后保存屏幕起点及窗口矩形，捕获鼠标；移动按屏幕坐标差更新，调用 EXE 的 `adjust_window_rect` 应用实时吸附设置；拉伸后限制皮肤最小尺寸和所在显示器工作区最大尺寸。音乐窗自己拖动只移动自己，主窗可带动相连窗口；已确认原版路径没有 Ctrl/Shift 临时取消吸附逻辑。详细旧证据见 [吸附分析与修复](SNAP_FIX.zh-CN.md)。

释放左键提交当前位置；外框 `WM_CANCELMODE` 或拖动期间 Esc 恢复起始矩形；捕获被抢走或隐藏窗口则结束当前拖动。当前分隔条和滚动滑块没有同样的取消还原状态机。没有外框中键、侧键或滚轮专用命令，也没有自定义右键拖窗；这些有界代码搜索不代表网页引擎不会处理相应按键。

**本轮实际验证的范围。** 独立 Win32/x86 探针加载当前 Release DLL，用自建隐藏 HWND 发送消息，下载流来自内存 IStream。没有移动真实鼠标、显示播放器窗口、启动浏览器、请求网络、操作已有播放器或执行删除。

| 探针动作 | 结果 |
|---|---|
| 下载中行双击 | `submit_tracks` 调用 1 次，参数为远程 URL |
| 下载中空白双击 | 调用 1 次，参数仍为旧选中项 |
| 已下载播放图标单击 | 调用 0 次 |
| 已下载行双击 | 调用 1 次，参数为本地文件 |
| 已下载空白双击 | 调用 1 次，参数仍为旧选中项 |
| 外框、分类空白、下载横幅、帮助按钮右击 | 各收到 1 次外框 `WM_CONTEXTMENU` |
| 列表空白、表头右击 | 外框 `WM_CONTEXTMENU` 为 0，列表自行吞掉 |

探针退出码为 0。它验证消息到命令的路径，不替代物理鼠标手感、菜单截图、原版标准控件默认行为、完整 EXE 消息过滤或网页 DOM 测试。最初探针调用漏传 enqueue 的必需输出指针，返回 `E_INVALIDARG`；修正的是探针参数，产品 DLL 未改。最终有效状态目录为 `probe/run5`。

当前 DLL 为 454656 字节，文件版本 `2026.10.22p4`，SHA-256 `c80421f09d8faa4c8c39ed948c1b61fd9ac9db78e9bac4ef4e6fb01c980ceb3e`。这与旧轮次记录的同版本产物哈希不同，本文探针以本次实际文件为准，不混用旧产物验证结论。两个原版 EXE 的 SHA-256 均为 `36ce61dfc6763f13c5d05620ccf2cfbc77bf04ffcee98d8d8a864daad616775a`。

**后续修正顺序建议。**

1. 移除外框通用右键与推荐/链接导航的耦合；按外框、网页、下载列表分别决定菜单和消息是否继续传递。不要为此一并关闭网页默认菜单。
2. 恢复下载中双击暂停/开始、已下载图标单击播放，并为双击加有效行检查；核对右键焦点与多选启禁。
3. 对齐删除文件的 Shell 可撤销语义、关联歌词选项和 Shift+Delete，避免菜单名称相同但结果不同。
4. 恢复底部外部链接、文字命中、手形和轮播，再补下载行提示、分隔条收起恢复、重复分类点击保留状态及表头分类开关。
