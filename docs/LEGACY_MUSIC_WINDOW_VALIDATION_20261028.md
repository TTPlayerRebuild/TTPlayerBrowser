## XP IE8 补测与按钮修补：p11

在 XP 注册表确认 IE 为 `8.0.6001.18702`。自动引擎选择使用实际 MSHTML 页面，状态返回 IE 标志；页面运行于支持 JSON 的标准模式，没有回退到原生列表。IE 使用兼容列表页面，专辑通过「打开」进入歌曲；WebView2 的专辑封面网格不属于 IE 页面的实现。

初次截图发现每行第三个操作按钮换行、齿轮字体显示为方框、专辑「打开」二字分行；窄窗口的歌曲说明也会被 `word-wrap:break-word` 强制折行。p11 使用 64×16 内嵌 PNG 图标带，统一播放/添加/下载/设置图标，调整操作列及按钮宽度、复选框边框和文字省略规则。同时兼容 IE8 的 `returnValue=false`，修复来源菜单方向键及 Esc 调用不存在的 `preventDefault()` 而失败的问题。

详情封面的实测样本为服务器返回的 42,985 字节 PNG，Base64 后超出 IE8 的 data URI 限制。IE 路径将超过 24,000 字节的封面等比缩放并填充为 96×96 JPEG；测试中 XP 的 data URI 缩至 4,751 字符，实际图片可见。WebView2 继续使用原始图片。测试读取 IE8 的原始 `src` 属性，不使用会进行 URL 规范化的 `.src` 属性断言格式和长度。

## 实现

- 「选项 → 网络连接 → 音乐窗」顶部增加「关闭 GPU 加速」，与下方的缓存、下载、媒体来源子页共用。Win7 缺省勾选，其他系统缺省不勾选；`Player/BrowserDisableGpu` 保存用户选择。
- 设置经可选 ABI 尾部字段传到 DLL。旧主程序和不完整的新字段仍可安全读取，旧 DLL 也能忽略新主程序的尾部字段。受保护内存页测试验证了读取边界。
- 个人媒体库和 Sayobot 使用同一 WebView2 环境创建函数，勾选时传递 `--disable-gpu`。软件绘制使用独立的浏览器数据目录，避免切换时复用参数不同但尚未退出的 Runtime 进程。设置不修改系统环境变量或 IE 配置。
- Sayobot 的所有入口和页面恢复共用 Runtime 可用性检查；XP 在调用 Loader 前被排除。Sayobot 初始化失败不会再走 IE 回退。原有 osu! 组件及可执行文件身份检查继续生效。
- 单曲「播放」按完整来源和子曲目复用已有行：正在打开/播放时不重新打开，暂停时继续，停止时重新打开原行。显式「添加」和专辑/批量提交保留插入语义，同名但不同 URL 的歌曲不会合并。
- XP 音乐窗淡入时直接取皮肤的透明色，避免窗口缩放后透明度查询失败而丢失透明色。
