# 音乐窗吸附分析与修复

日期：2026-10-22。组件版本：`2026.10.22p3`。

## 缺失原因

音乐窗改为无系统边框的皮肤窗口后，`BrowserWindow::ContinueBackgroundDrag` 自行计算鼠标位移并直接调用 `SetWindowPos`。主程序虽然已经将音乐窗 HWND 放进 `RegisteredDragWindows()`，但 DLL 发起拖动时没有回到主程序的吸附路径。因此主窗可以把音乐窗当成目标、也可以带动已贴合的音乐窗，音乐窗自己拖动和缩放却没有磁吸。

## 原版依据

本次复用已保存的 REA / Ghidra 证据，并核对两个指定安装目录中的 `TTPlayer.exe`；未运行或修改原版程序。

- 两个 5790x/z 文件的 SHA-256 均为 `36ce61dfc6763f13c5d05620ccf2cfbc77bf04ffcee98d8d8a864daad616775a`。
- 原全量反编译输入与这些文件不是同一文件。本次核对 29 个相关函数范围，其中 28 个字节完全相同；创建函数存在差异，改用直接针对 5790z 的 REA 汇编证据确认，不能将整个旧分析文件视为相同版本。
- 构造链 `0040C9A7 → 0048AC21 → 0044F3CF` 初始化磁吸距离 10；创建函数 `0040D5C3` 在 `0040D8F5` 调用公共登记路径，销毁函数 `0040D90A` 注销 HWND。
- 移动路径 `0041094D / 0044F804` 对工作区及可见注册窗计算最近边界修正，距离恰好 10 像素仍吸附。窗口间另一轴须重叠或相距不超过阈值。
- `0046857C` 将宿主吸附配置同步到音乐窗；音乐窗不应自行硬编码独立阈值。
- 主窗发起的拖动可形成传递附着组。音乐窗独立拖动只调整自身，`004107FD` 检查的是主窗身份。已核对路径未发现 Ctrl/Shift 关闭吸附判断。
- 缩放路径 `004709A2` 只调整被拖动边，从工作区及可见注册窗的边取最近值，随后限制最小/最大尺寸；缩放候选不要求另一轴重叠。

## 实现

在 `ttp_browser_host` 尾部追加可选的 `adjust_window_rect` 回调：DLL 提供屏幕坐标矩形和 Windows 的 `HTCAPTION / HTLEFT…HTBOTTOMRIGHT` 命中值，宿主按当前设置修正候选矩形。此回调只在 UI 线程调用，关闭宿主回调后会被拒绝。

主程序实时读取 `General/Snap_Windows`：默认 `65546`（`0x1000A`，开启且距离 10），使用与其他面板相同的设置解码和窗口登记表。移动复用 `ComputeDragSnapCorrection`；缩放只修改活动边。主窗、列表、歌词、均衡器及注册的 DSP 窗口均可成为可见吸附目标，音乐窗自身和隐藏目标被排除。

DLL 保留自己的鼠标捕获、取消拖动和八方向缩放，并在磁吸后执行皮肤最小尺寸、工作区最大尺寸限制。没有添加系统缩放边框。主窗发起的传递附着组沿用现有实现，音乐窗发起的拖动不反向移动主窗。

原版使用 `SPI_GETWORKAREA`；重建版继续按候选位置所在显示器读取工作区，避开任务栏。这是新系统适配，不是本次证据证明的原版多显示器能力。

## 接口兼容与部署

ABI 仍为版本 1。通过结构 `size` 判断新回调是否完整存在，旧前缀使用固定长度复制，不读取尾部缺失或不完整的指针。旧宿主仍可加载新 DLL；旧 DLL 也能接受增加字段的新宿主，但旧组合不会获得本次完整吸附功能。

**本次修复需要同时更新 `TTPlayerRebuild.exe` 和 `ttpbrowser.dll`。** 单独替换 DLL 无法让旧 EXE 提供吸附回调。组件仍是可选 DLL，缺失或不兼容时继续隐藏相关入口。WebView2 Loader 仍静态合并在组件中。

本地已更新 `rebuild/build/Release` 的配套 EXE 和 DLL，请重新从该目录启动。工作区根目录保留旧运行库组合，未在本轮升级；部署详情见 [BUILD_VALIDATION.md](BUILD_VALIDATION.md)。
